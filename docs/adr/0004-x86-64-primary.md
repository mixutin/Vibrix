# ADR-0004: x86-64 as the primary architecture

- **Status:** Accepted
- **Date:** 2026-09-27
- **Deciders:** Project bootstrap

## Context

The primary target architecture determines the CPU feature set, boot process, and hardware interfaces Vibrix must support. Options include x86-64, aarch64, and RISC-V.

## Decision

x86-64 (AMD64) is the primary architecture. The development reference is QEMU with OVMF. The physical reference is Target 001 (see `targets/target-001/`).

## Consequences

- **Hardware availability:** x86-64 is widely available on both virtual and physical hardware. Target 001 provides a known physical reference.
- **Documentation:** x86-64 has extensive documentation from Intel and AMD, plus the UEFI specification.
- **Complexity:** x86-64 has a large legacy surface (segmentation, paging modes, APIC variants). Vibrix must implement a subset and ignore the rest.
- **Future:** aarch64 is listed as a future goal. The architecture-independent boundaries in the codebase should be designed to accommodate this.

## Alternatives considered

- **aarch64:** Growing in popularity (Apple Silicon, ARM servers). Rejected as primary because the physical reference hardware (Target 001) is x86-64. Listed as a future goal.
- **RISC-V:** Open ISA with clean design. Rejected as primary because hardware availability and firmware support (UEFI on RISC-V) are less mature.
- **i386 (32-bit x86):** Rejected because 64-bit addressing, larger register file, and modern firmware support make x86-64 strictly better for a new OS.
