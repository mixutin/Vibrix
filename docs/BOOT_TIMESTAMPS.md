# Boot IDs and structured-log timestamps

Each boot may initialize structured logging metadata from two independent
sources:

- a 128-bit boot identifier generated by the existing fail-closed RDSEED secure
  random service; and
- a stable CMOS RTC UTC snapshot used as the wall-clock anchor.

The existing 100 Hz PIT interrupt increments the log clock's monotonic tick
counter. Every newly published structured kernel record stores the boot ID,
monotonic tick count and wall-clock seconds computed from the RTC anchor plus
whole elapsed PIT seconds. Published records remain immutable.

If secure random or the RTC is unavailable, initialization fails explicitly;
the kernel does not synthesize a supposedly unique ID from time, PCI identity,
MAC addresses or other stable hardware identifiers. The ordinary supported QEMU
evidence path requires successful initialization.

The current x86 RTC policy accepts years 2000 through 2099 because no validated
FADT century-register contract exists yet. Timestamps are second-resolution and
the PIT is not a precision time source; NTP discipline and persistent journals
remain separate roadmap work.
