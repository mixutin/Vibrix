EXPERIMENTAL OS · NATIVE DESKTOP PREVIEW

Your system.
In your pocket.

Vibrix is an independent, Rust-native operating system designed to live persistently on a removable USB drive. Not Linux underneath. The vision is portable; today's QEMU build includes our own kernel, a real Ring 3 shell and an opt-in native desktop preview. Chromium and persistent root are not running yet.

01 / THE IDEA

An OS that goes
where you go.

The goal is one removable system drive carrying root, applications, settings and your home directory. Persistence is part of the architecture, not an afterthought.

Future compatible machines will rediscover the hardware at boot. Native USB storage and persistent root are still engineering milestones, not features available today.

03 / BUILD STATUS

From first boot
to real OS.

This snapshot is based on merged main and observed QEMU behavior. Partial foundations do not mean the whole milestone is complete.

✓
M0–M2 / BOOT PATH

Boot & handoff

UEFI → our loader → standalone higher-half kernel with BootInfo v3.

◌
M3 / FOUNDATIONS VERIFIED

Memory & exceptions

Frames, early heap, dynamic managed mappings/reclaim, guard pages and CPU fault probes; general user-process scheduling and SMP remain unfinished.

◌
M4

Device discovery & interrupts

ACPI, PCI/BAR, bounded ECAM, driver binding and real single-vector MSI delivery on the isolated QEMU EDU device. MSI-X delivery and general hardware drivers remain separate.

✓
M4.5 / QEMU VERIFIED

Interactive kernel console

Real virtual keys, line editing, diagnostics, timer and a working vibrix> prompt.

◌
M5–M6 / NATIVE USERSPACE

Userspace CLI and desktop preview

Real Ring 3 ELF, syscalls, RAM files and a documented shell; opt-in graphical terminal and file viewer. Not a general process environment or browser.

·
M7–M9 / FUTURE

Persistent USB OS

Native USB storage and filesystem integration. GPT/VibrixFS host tools already have narrower test coverage.

08 / BUILD PHILOSOPHY

Independent.
Not isolated.

Agents must research primary specifications and upstream libraries, compare reasonable approaches, document provenance and licenses, and test actual target compatibility. Crates.io packages, reviewed Git revisions and properly licensed vendored crates are welcome.

CI checks known advisories, licenses, sources, lockfiles and features. It is not proof that every dependency is safe or that all host software was audited. Read the admission paths and coverage limits.
